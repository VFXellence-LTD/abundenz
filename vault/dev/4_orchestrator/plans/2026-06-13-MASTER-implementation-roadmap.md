## Cross-cutting conventions (apply to every plan)

- **Worktree isolation:** Plans 1–4 (software) execute per-task in a git worktree via `superpowers:using-git-worktrees`. **Plan 0 does NOT use worktrees** — it manipulates `.git` itself (re-root) and the working tree layout; it runs on the main checkout with backups + a safety tag.
- **Dynamic model/effort routing per task** (from `.canon`/vault routing doctrine):
  - mechanical (file/dir moves, gitignore, renames, changelog) → **haiku**, low effort
  - content reconciliation / merge-with-judgment → **sonnet**, medium effort
  - schema design, PTY driver port, engine logic, git re-root surgery → **opus**, high effort
- **Commits:** imperative summary < 72 chars, blank line, bullets. No co-author lines. `git -C <path>` (never `cd && git`).
- **Boss checkpoints:** the git re-root (Plan 0 Task 2), any deletion (Plan 0 Task 9), and each plan's completion are hard gates.

## MVP definition (the finish line for Plans 0–4)

ONE Zrodinger clip **draft** — generated by a spawned Claude Code session, safeguard-checked, written to disk, surfaced in the Approval Queue, **approved by Boss** — tracked end-to-end in SQLite, governed by `.canon`. **No publish. No social accounts.**

## Scaling model (Plan S — sketch, detailed after MVP)

Once one draft is proven: parallelise. Multiple campaigns → multiple `agent_runs` → a pool of spawned Claude sessions (bounded by budget cap + concurrency limit), each producing drafts into the per-ecosystem-scoped Approval Queue. Autonomy climbs the ladder (Stage 0→3) per pipeline as each proves 30 days. Brand isolation holds via scoping middleware. Publish stays human. Detailed once the single-campaign loop is real — not before (pitfalls #9/#14).
