# References

R&D inbox for the polymath system. Drop links here as you find them; process them on a schedule rather than ad-hoc.

## Why this exists

Workflow ideas, tools, and creator strategies live across reels, threads, articles, and papers. Without a single capture point, good ideas get lost and you end up rebuilding things you already saw working elsewhere. This folder is the brain's external scratchpad.

## How to use it

**On capture (5 seconds):** drop the raw link into `_inbox.md` with one line of why it caught your attention. Don't process yet.

**On review (weekly, ~20 min):** move each inbox item into the right subfolder using the template in `_TEMPLATE.md`. Anything that isn't worth a 5-min writeup gets deleted, not archived. Be ruthless — references that aren't actionable are noise.

**On synthesis (monthly):** read everything in each subfolder. Promote anything that's actually shaped your workflow into `/.polymath/playbooks/` with attribution back to this folder.

## Subfolders

| Folder | What goes here |
|---|---|
| `reels/` | Instagram, TikTok, YouTube Shorts — short-form workflow demos |
| `videos/` | Long-form YouTube, conference talks, tutorials |
| `articles/` | Blog posts, newsletters, written guides |
| `threads/` | X threads, LinkedIn posts, Reddit threads worth preserving |
| `tools/` | Specific tools/SaaS to evaluate (one file per tool) |
| `creators/` | People whose entire body of work is worth tracking |
| `papers/` | Research papers, technical documentation |

## Naming convention

`YYYY-MM-DD_short-slug.md`

Example: `2026-05-03_ai-headless-video-pipeline.md`

The date is when YOU captured it, not when it was published. This makes review-by-recency trivial.

## Quality bar

A reference earns its place in a subfolder only if you can answer: **"What would I steal from this for the polymath system?"** If the answer is "nothing specific yet, but it's interesting," it stays in `_inbox.md` or gets deleted.
