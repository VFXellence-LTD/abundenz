System Map

Mission Control is a monorepo workspace at D:\VFXellence-LTD\.canon\.mission-control\. Two packages: client (Vite + React 19, port 5174) and server (Express + better-sqlite3, port 4500). Agent engine lives at D:\VFXellence-LTD\polymath\packages\agents\ and is invoked via PTY sessions spawned by the server.

Browser (5174)
  └─ Vite proxy /api/* → localhost:4500
  └─ Vite proxy /ws    → localhost:4500  (WebSocket status bus)
  └─ Vite proxy /ws/terminal → localhost:4500  (xterm.js PTY)

Express (4500)
  ├─ REST routes (transactions, tools, setup, launch, tasks, campaigns, approvals, artifacts, agent-runs, sessions, vault, publish, bug-report)
  ├─ WS /ws          → EventEmitter status bus
  └─ WS /ws/terminal → node-pty ↔ xterm.js

node-pty spawns:
  └─ claude --resume <uuid>  (or skill entry-points)
     └─ packages/agents/src/  (generate driver, render driver, safeguard, publish)

Safeguard Rules

Hard blocks (draft halted, BLOCKED- prefix)

  • Hate speech
  • Health fabrications: "100% safe/effective", "cures cancer", "miracle cure"
  • Financial guarantees without disclaimer
  • Weak hook openers: "hey guys", "so today", "in this video", "welcome back", "what's up"

Soft flags (approval note, not blocked)

  • Missing FTC disclosure when CTA present
  • Missing AI-disclosure
  • Unverified sources
Enforcement mismatch: publish.service.ts hard-blocks Affiliate ecosystem on missing affiliateDisclosure. validateDraft.ts in agents only soft-flags the same rule. Two different enforcement levels for the same FTC rule.

Dry-Run Discipline

Three independent dry-run layers. Each is individually gated. None shares state with the others.

Layer 1 — Bug Report

MC_BUG_REPORT_ENABLED absent  →  log "[bug-report] WOULD CREATE ISSUE", return { dryRun: true }
MC_BUG_REPORT_ENABLED=true    →  gh issue create --repo VFXellence-LTD/vfxellence ...

Client shows amber banner on modal when dryRun: true.

Layer 2 — Publish

BUFFER_TOKEN absent            →  DryRunDistributor  (all publishes)
BUFFER_TOKEN present but
  credential_ref missing        →  DryRunDistributor  (that account)
  credential_ref env key unset  →  DryRunDistributor  (that account)
No active routing accounts      →  legacy path        →  same credential check
All paths write publish_log with dry_run = 0 or 1

Layer 3 — Render (three independent sub-gates)

ELEVENLABS_API_KEY absent       →  voice placeholder .mp3
HF_PATH absent + no hf.exe      →  visual placeholder .png per shot
HYPERFRAMES_ENABLED != "true"   →  assembly placeholder .mp4

Any one dry  →  RenderReport.dryRun = true  →  "DRY RUN" badge in Approvals UI

Multi-Account Routing (Module 1)

What is implemented

  • platform_accounts schema with all routing columns (migrations applied)
  • RoutingService.buildPlan(): pure read — orders active accounts by last_posted_at IS NULL first, then oldest post, then rotation_order; staggers by stagger_hours; caps at maxAccountsPerPlatform (default 1)
  • CredentialResolver.resolve(ref, env): maps credential_ref → env var → Buffer profileId
  • 16 scoped DB views include platform_accounts data

What is NOT implemented (operational gaps)

Routing is a no-op in production. Four gaps:
  1. publish.service.ts does NOT call RoutingService — still uses legacy selectDistributor() (Task 4 of routing plan, not done)
  2. platform_accounts.last_posted_at is never written back after publish (Task 4B)
  3. BufferDistributor.profileIds = [] — stub, not wired to CredentialResolver (Task 4A)
  4. No UI to seed platform_accounts rows — manual SQLite INSERT required
Net result: buildPlan() returns empty list → every publish falls through to legacy single-account path.
